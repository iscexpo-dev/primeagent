The [Primeagent runtime Helm chart](https://github.com/khulnasoft-bot/primeagent-helm-charts/blob/main/charts/primeagent-runtime) is tailored for deploying applications in a production environment. It is focused on stability, performance, isolation, and security to ensure that applications run reliably and efficiently.

:::warning
For security reasons, the default Primeagent runtime Helm chart sets [`readOnlyRootFilesystem: true`](https://github.com/khulnasoft-bot/primeagent-helm-charts/blob/main/charts/primeagent-runtime/values.yaml#L46). This setting prevents modifications to the container's root filesystem at runtime, which is a recommended security measure in production environments.

If `readOnlyRootFilesystem` is disabled (`false`), it degrades your deployment's security posture. Only disable this setting if you understand the security implications and you have implemented other security measures.

For more information, see the [Kubernetes documentation](https://kubernetes.io/docs/tasks/configure-pod-container/security-context/).
:::

## Prerequisites

- A [Kubernetes](https://kubernetes.io/docs/setup/) server
- [kubectl](https://kubernetes.io/docs/tasks/tools/#kubectl)
- [Helm](https://helm.sh/docs/intro/install/)

## Install the Primeagent runtime Helm chart

1. Add the repository to Helm:

    ```shell
    helm repo add primeagent https://khulnasoft-bot.github.io/primeagent-helm-charts
    helm repo update
    ```

2. Create the `primeagent` namespace and generate a superuser password and API key:

    ```shell
    kubectl create namespace primeagent
    export PRIMEAGENT_SUPERUSER_PASSWORD=$(openssl rand -base64 32)
    export PRIMEAGENT_API_KEY=$(openssl rand -hex 32)
    kubectl create secret generic primeagent-auth \
      --namespace primeagent \
      --from-literal=PRIMEAGENT_SUPERUSER_PASSWORD="$PRIMEAGENT_SUPERUSER_PASSWORD" \
      --from-literal=PRIMEAGENT_API_KEY="$PRIMEAGENT_API_KEY"
    ```

    Store both generated values securely.

3. Download the chart's default configuration:

    ```shell
    helm show values primeagent/primeagent-runtime > primeagent-values.yaml
    ```

4. In `primeagent-values.yaml`, add these entries to the existing `env` list:

    ```yaml
      - name: PRIMEAGENT_AUTO_LOGIN
        value: "false"
      - name: PRIMEAGENT_SUPERUSER_PASSWORD
        valueFrom:
          secretKeyRef:
            name: primeagent-auth
            key: PRIMEAGENT_SUPERUSER_PASSWORD
      - name: PRIMEAGENT_API_KEY_SOURCE
        value: "env"
      - name: PRIMEAGENT_API_KEY
        valueFrom:
          secretKeyRef:
            name: primeagent-auth
            key: PRIMEAGENT_API_KEY
    ```

    Keep the existing entries in the list. For more information, see [API keys and authentication](/api-keys-and-authentication).

5. Install the Primeagent app with your configuration in the `primeagent` namespace.

    <Tabs groupId="">
    <TabItem value="Install chart with custom image" label="Install chart with custom image" default>

    If you have a [custom image with packaged flows](/deployment-docker#package-your-flow-as-a-docker-image), you can deploy Primeagent by overriding the default [`values.yaml`](https://github.com/khulnasoft-bot/primeagent-helm-charts/blob/main/charts/primeagent-runtime/values.yaml) with the `--set` flag:

    ```shell
    helm install my-primeagent-app primeagent/primeagent-runtime \
      --namespace primeagent \
      --values primeagent-values.yaml \
      --set image.repository=myuser/primeagent-hello-world \
      --set image.tag=1.0.0
    ```

    </TabItem>
    <TabItem value="Install chart and download flow" label="Install chart and download flow">

    Install the chart and download flows from a URL with the `--set` flag:

    ```shell
    helm install my-primeagent-app-with-flow primeagent/primeagent-runtime \
      --namespace primeagent \
      --values primeagent-values.yaml \
      --set 'downloadFlows.flows[0].url=https://raw.githubusercontent.com/khulnasoft-bot/primeagent/dev/tests/data/basic_example.json'
    ```

    If your shell requires escaping square brackets, modify the `--set` path as needed.
    For example, `--set 'downloadFlows.flows\[0\].url=https://raw.githubusercontent.com/khulnasoft-bot/primeagent/dev/tests/data/basic_example.json'`.

    </TabItem>
    </Tabs>

6. Check the status of the pods:

    ```shell
    kubectl get pods -n primeagent
    ```

## Access the Primeagent runtime

1. Get your service name:

    ```shell
    kubectl get svc -n primeagent
    ```

    The service name is your release name suffixed by `-primeagent-runtime`. For example, if you used `helm install my-primeagent-app-with-flow`, then the service name is `my-primeagent-app-with-flow-primeagent-runtime`.

2. Enable port forwarding to access Primeagent from your local machine:

    ```shell
    kubectl port-forward -n primeagent svc/my-primeagent-app-with-flow-primeagent-runtime 7860:7860
    ```

3. Confirm you can access the API by calling `http://localhost:7860/api/v1/flows/` with the API key generated during installation:

    ```shell
    curl -v \
      --header "x-api-key: $PRIMEAGENT_API_KEY" \
      http://localhost:7860/api/v1/flows/
    ```

    A successful request returns a list of flows.

4. Run a packaged flow.
The following example gets the first flow ID from the flows list, and then runs the flow:

    ```shell
    # Get flow ID
    id=$(curl -s \
      --header "x-api-key: $PRIMEAGENT_API_KEY" \
      "http://localhost:7860/api/v1/flows/" | jq -r '.[0].id')

    # Run flow
    curl -X POST \
        "http://localhost:7860/api/v1/run/$id?stream=false" \
        -H 'Content-Type: application/json' \
        -H "x-api-key: $PRIMEAGENT_API_KEY" \
        -d '{
          "input_value": "Hello!",
          "output_type": "chat",
          "input_type": "chat"
        }'
    ```

## Configure secrets and environment variables

Use the `env` section of the Primeagent runtime Helm chart's [`values.yaml`](https://github.com/khulnasoft-bot/primeagent-helm-charts/blob/main/charts/primeagent-runtime/values.yaml) file to define environment variables for your Primeagent deployment.
This includes built-in [Primeagent environment variables](/environment-variables), as well as [global variables](/configuration-global-variables) used by your flows.

Primeagent can source global variables from your runtime environment, such as Kubernetes secrets referenced in `values.yaml`.
For example, the Primeagent runtime Helm chart's [example flow JSON](https://raw.githubusercontent.com/khulnasoft-bot/primeagent-helm-charts/refs/heads/main/examples/flows/basic-prompting-hello-world.json) uses a global variable that is a secret.
If you want to run this flow in your Primeagent deployment on Kubernetes, you need to include the secret in your runtime configuration.

:::tip
When you export flows as JSON files, it's recommended to omit secrets.
Whether or not a secret is included depends on how you declare the secret in your flow and whether you use the **Save with my API keys** option.
For more information, see [Import and export flows](/concepts-flows-import).
:::

### Set secrets

Kubernetes secrets are the recommended way to store sensitive values and credentials.

Use `secretKeyRef` to reference a Kubernetes secret in `values.yaml`:

```yaml
env:
  - name: OPENAI_API_KEY
    valueFrom:
      secretKeyRef:
        name: openai-credentials
        key: openai-key
```

<details>
<summary>Create and set secrets with `kubectl` and `helm`</summary>

You can use `kubectl` and `helm` commands to create and set secrets:

1. Create a secret:

    ```shell
    kubectl create secret generic openai-credentials \
      --namespace primeagent \
      --from-literal=OPENAI_API_KEY=sk...
    ```

2. Verify the secret exists:

    ```shell
    kubectl get secrets -n primeagent openai-credentials
    ```

    The result is encrypted.

3. Add the following entry to the existing `env` list in `primeagent-values.yaml`:

    ```yaml
      - name: OPENAI_API_KEY
        valueFrom:
          secretKeyRef:
            name: openai-credentials
            key: OPENAI_API_KEY
    ```

4. Upgrade the Helm release:

    ```shell
    helm upgrade my-primeagent-app primeagent/primeagent-runtime \
      --namespace primeagent \
      --values primeagent-values.yaml
    ```

</details>

### Set the log level and other configuration variables

For non-sensitive variables, such as `PRIMEAGENT_LOG_LEVEL`, you can set the value directly in `values.yaml`:

```yaml
env:
  - name: PRIMEAGENT_LOG_LEVEL
    value: "INFO"
```

## Configure scaling

Use `replicaCount` and `resources` in the Primeagent runtime Helm chart's [`values.yaml`](https://github.com/khulnasoft-bot/primeagent-helm-charts/blob/main/charts/primeagent-runtime/values.yaml) file to configure scaling:

* **Horizontal scaling**: Use `replicaCount` to set the number of replicas for your Primeagent deployment.

    ```yaml
    replicaCount: 3
    ```

* **Vertical scaling**: Use the `resources` section to adjust pod resources depending on your application's needs.

    ```yaml
    resources:
      requests:
        memory: "2Gi"
        cpu: "1000m"
    ```
