Running applications in Docker containers ensures consistent behavior across different systems and eliminates dependency conflicts.

Primeagent publishes base, default, and extended application images with different
provider inventories. Before deploying, see
[Choose a Primeagent Docker image](./docker-image-profiles.mdx) for the
canonical tags, composition, version-pinning, migration, and rollback guidance.

This guide demonstrates several ways to run Primeagent with [Docker](https://docs.docker.com/) and [Docker Compose](https://docs.docker.com/compose/):

* [Quickstart](#quickstart): Start a Primeagent container with default values.
* [Use Docker Compose](#docker-compose): Run Primeagent with a persistent PostgreSQL database and configurable environment variables.
* [Customize the Docker Compose file](#customize): Package a flow or add your own code into a custom image built on top of the official Primeagent image.
* [Build and run the Docker image from source](#build-from-source): Build a Docker image from a local clone of the repo, or start a full development environment with hot reload on both frontend and backend.
* [Upgrade the Primeagent Docker image](#upgrade-the-primeagent-docker-image): Upgrade to a newer image without losing your database or flows.
* [Docker image defaults](#docker-image-security-defaults): Environment variables included in the Primeagent image and how to override them.

## Quickstart {#quickstart}

With Docker installed and running on your system, run the following command:

    ```bash
    docker run -p 7860:7860 \
      -e PRIMEAGENT_AUTO_LOGIN=false \
      -e PRIMEAGENT_SUPERUSER_PASSWORD=SUPERUSER_PASSWORD \
      khulnasoft/primeagent:latest
    ```

    By default, the official Docker images set `PRIMEAGENT_AUTO_LOGIN=false` by default.

    Replace `SUPERUSER_PASSWORD` with a strong password for the Primeagent superuser.

    For more information, see [Docker image defaults](#docker-image-security-defaults).

Then, access Primeagent at `http://localhost:7860/`.

This starts a pre-built Docker image with automatic login enabled for local development.
For more control over the configuration, see [Use Docker Compose](#docker-compose).

## Use Docker Compose {#docker-compose}

Docker Compose gives you more control over your configuration, such as setting environment variables, using a persistent PostgreSQL database instead of the default SQLite database, and including custom dependencies.

The Primeagent repo includes a ready-to-use Compose file at `docker_example/docker-compose.yml` that pulls the latest Primeagent image from Docker Hub and includes persistent volume storage with PostgreSQL.

1. Clone the Primeagent repository:

   ```shell
   git clone https://github.com/khulnasoft-bot/primeagent.git
   ```

2. Navigate to the `docker_example` directory:

   ```shell
   cd primeagent/docker_example
   ```

3. Run the Docker Compose file:

   ```shell
   docker compose up
   ```

4. Access Primeagent at `http://localhost:7860/`.

## Customize the Docker Compose file {#customize}

Customize the Docker Compose file to fit your deployment's requirements.

### Include environment variables

Configure a container's database credentials using a `.env` file.

1. Create a `.env` file with your database credentials in the same directory as `docker-compose.yml`:

    ```text
    # Database credentials
    POSTGRES_USER=myuser
    POSTGRES_PASSWORD=mypassword
    POSTGRES_DB=primeagent

    # Primeagent configuration
    PRIMEAGENT_DATABASE_URL=postgresql://myuser:mypassword@postgres:5432/primeagent
    PRIMEAGENT_CONFIG_DIR=/app/primeagent
    PRIMEAGENT_SUPERUSER_PASSWORD=SUPERUSER_PASSWORD
    ```

    Replace `SUPERUSER_PASSWORD` with a strong password for the Primeagent superuser.

2. Edit `docker-compose.yml` to replace the hardcoded values with variable references for both the `primeagent` and `postgres` services:

    ```yaml
    services:
      primeagent:
        environment:
          - PRIMEAGENT_DATABASE_URL=${PRIMEAGENT_DATABASE_URL}
          - PRIMEAGENT_CONFIG_DIR=${PRIMEAGENT_CONFIG_DIR}
          - PRIMEAGENT_SUPERUSER_PASSWORD=${PRIMEAGENT_SUPERUSER_PASSWORD}
      postgres:
        environment:
          - POSTGRES_USER=${POSTGRES_USER}
          - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
          - POSTGRES_DB=${POSTGRES_DB}
    ```

    With variable references in place, Docker Compose reads the values from your `.env` file at startup.

For a complete list of available environment variables, see [Primeagent environment variables](/environment-variables).

### Package a flow into the image {#package-your-flow-as-a-docker-image}

Embed a flow JSON directly into a Docker image.
This is useful for distributing a specific flow as a standalone container or deploying it to environments like Kubernetes.

1. Create a project directory and change into it:

    ```bash
    mkdir primeagent-custom && cd primeagent-custom
    ```

2. Add your flow's JSON file to the directory. You can download an example, or use your own:

    ```bash
    # Download an example flow
    wget https://raw.githubusercontent.com/khulnasoft-bot/primeagent-helm-charts/refs/heads/main/examples/flows/basic-prompting-hello-world.json

    # Or copy your own flow file
    cp /path/to/your/flow.json .
    ```

3. Create a `Dockerfile`:

    ```dockerfile
    FROM khulnasoft/primeagent:latest
    RUN mkdir /app/flows
    COPY ./*.json /app/flows/
    ENV PRIMEAGENT_LOAD_FLOWS_PATH=/app/flows
    ```

4. Build, test, and optionally push your image:

    ```bash
    docker build -t myuser/primeagent-custom:1.0.0 .
    docker run -p 7860:7860 -e PRIMEAGENT_AUTO_LOGIN=true myuser/primeagent-custom:1.0.0
    docker push myuser/primeagent-custom:1.0.0  # optional
    ```

For Kubernetes deployment, see [Deploy the Primeagent production environment on Kubernetes](/deployment-kubernetes-prod).

### Add custom code or dependencies {#customize-the-primeagent-docker-image}

Patch custom code into the pre-built image's installation.
This is useful when you need to add custom Python packages, replace a built-in component, or make targeted changes without a [full source build](#build-from-source).

This example replaces the built-in **Message History** component, but the same pattern applies to any component or file.

1. Create a directory for your custom Primeagent setup:

    ```bash
    mkdir primeagent-custom && cd primeagent-custom
    ```

2. Create the directory structure that mirrors the component path:

    ```bash
    mkdir -p src/wfx/src/wfx/components/models_and_agents
    ```

3. Place your modified `memory.py` file in that directory.

4. Create a `Dockerfile`:

    ```dockerfile
    FROM khulnasoft/primeagent:latest

    WORKDIR /app

    COPY src/wfx/src/wfx/components/models_and_agents/memory.py /tmp/memory.py

    RUN python -c "import site; print(site.getsitepackages()[0])" > /tmp/site_packages.txt

    RUN SITE_PACKAGES=$(cat /tmp/site_packages.txt) && \
        mkdir -p "$SITE_PACKAGES/wfx/components/models_and_agents" && \
        cp /tmp/memory.py "$SITE_PACKAGES/wfx/components/models_and_agents/"

    RUN SITE_PACKAGES=$(cat /tmp/site_packages.txt) && \
        find "$SITE_PACKAGES" -name "*.pyc" -delete && \
        find "$SITE_PACKAGES" -name "__pycache__" -type d -exec rm -rf {} +

    EXPOSE 7860
    CMD ["python", "-m", "primeagent", "run", "--host", "0.0.0.0", "--port", "7860"]
    ```

5. Build and run the image:

    ```bash
    docker build -t myuser/primeagent-custom:1.0.0 .
    docker run -p 7860:7860 -e PRIMEAGENT_AUTO_LOGIN=true myuser/primeagent-custom:1.0.0
    ```

## Build and run the Docker image from source {#build-from-source}

:::tip
Both `make docker_build` and `make wfx_docker_build` use Podman by default. If you have Docker installed instead, pass the alias `DOCKER=docker` on the command line:

```shell
make docker_build DOCKER=docker
```
:::


If you've cloned the Primeagent repository and want to build and run your local changes inside a Docker container, run:

    ```shell
    make docker_build
    ```

This builds `docker/build_and_push.Dockerfile` and tags the result `primeagent:<version>`.

To run the image after building, run:

```shell
docker run -p 7860:7860 \
  -e PRIMEAGENT_SUPERUSER_PASSWORD=SUPERUSER_PASSWORD \
  primeagent:VERSION
```

Replace the following:

* `SUPERUSER_PASSWORD`: a strong password for the Primeagent superuser
* `VERSION`: the version in `pyproject.toml` at the repo root

The image sets `PRIMEAGENT_AUTO_LOGIN=false`, so a superuser password is required unless you set `PRIMEAGENT_AUTO_LOGIN=true`.
For more information, see [Docker image defaults](#docker-image-security-defaults).

To build only the WFX executor CLI image instead of the full Primeagent application, run:

```shell
make wfx_docker_build
```

This builds `src/wfx/docker/Dockerfile` and tags the result `wfx:latest`.
It produces a lightweight Alpine-based image that contains only the `wfx` CLI tool, with no frontend or Primeagent UI.

The build context is the repo root, not `src/wfx/`. The Dockerfile copies from `pyproject.toml`, `uv.lock`, `src/wfx/`, and `src/sdk/`, so the full workspace is sent to the daemon. A root `.dockerignore` file partially mitigates this, but the first build will be slower than you might expect for a small CLI image.

### Write a custom source-based Dockerfile

When writing a source-based Dockerfile, you must copy the manifest files (`pyproject.toml`, `README.md`, and `uv.lock` where present) for the workspace members that `uv sync` needs to resolve dependencies before source is available.
The workspace members are defined in `[tool.uv.workspace]` in the root `pyproject.toml`.
You do not need to copy manifests for members like `src/primeagent-stepflow` that are not required for the initial dependency-only sync.
The full source is copied later with `COPY ./src`, which brings those omitted members into the image before the second `uv sync`.

1. To copy all manifest files to your Dockerfile, include the following:

    ```dockerfile
    COPY ./uv.lock /app/uv.lock
    COPY ./README.md /app/README.md
    COPY ./pyproject.toml /app/pyproject.toml
    COPY ./src/backend/base/README.md /app/src/backend/base/README.md
    COPY ./src/backend/base/pyproject.toml /app/src/backend/base/pyproject.toml
    COPY ./src/wfx/README.md /app/src/wfx/README.md
    COPY ./src/wfx/pyproject.toml /app/src/wfx/pyproject.toml
    COPY ./src/sdk/README.md /app/src/sdk/README.md
    COPY ./src/sdk/pyproject.toml /app/src/sdk/pyproject.toml
    COPY ./src/bundles /app/src/bundles
    ```

2. To install dependencies and copy the source, include the following:

    ```dockerfile
    RUN --mount=type=cache,target=/root/.cache/uv \
        uv sync --frozen --no-install-project --no-editable --extra postgresql --no-group dev

    COPY ./src /app/src

    RUN --mount=type=cache,target=/root/.cache/uv \
        uv sync --frozen --no-editable --extra postgresql --no-group dev
    ```

    The first `uv sync` installs only dependencies before the source is copied, so that Docker can cache that layer. The second `uv sync` installs the project packages (`primeagent`, `wfx`) from the copied source. Both calls are required. Omitting the second will produce a container with all dependencies present but the project packages missing, which fails at runtime.

The supported source build uses
[`docker/build_and_push.Dockerfile`](https://github.com/khulnasoft-bot/primeagent/blob/main/docker/build_and_push.Dockerfile).
Build its `base` target for the bundle-free application, `full` for the normal
curated distribution, or `full-bundles` for the extended provider inventory.

### Start a development environment with `make dcdev_up`

`make dcdev_up` starts a full development environment from source using [`docker/dev.docker-compose.yml`](https://github.com/khulnasoft-bot/primeagent/blob/main/docker/dev.docker-compose.yml).
This is useful if you want to work on the Primeagent codebase within a container.

To build the Primeagent dcdev image, run:

```shell
make dcdev_up
```

Access the backend and Primeagent UI at  `http://localhost:7860/`.
Access the frontend dev server at `http://localhost:3000/`.

The following environment variables are set by default:

| Variable | Default value | Description |
|---|---|---|
| `PRIMEAGENT_DATABASE_URL` | `postgresql://primeagent:primeagent@postgres:5432/primeagent` | PostgreSQL connection string |
| `PRIMEAGENT_SUPERUSER` | `primeagent` | Initial admin username |
| `PRIMEAGENT_CONFIG_DIR` | `/var/lib/primeagent` | Directory for Primeagent config and data |

`PRIMEAGENT_SUPERUSER_PASSWORD` is not set in the compose file. With the default `PRIMEAGENT_AUTO_LOGIN=true`, Primeagent generates a random bootstrap password for the auto-login account. If you set `PRIMEAGENT_AUTO_LOGIN=false`, you must set `PRIMEAGENT_SUPERUSER_PASSWORD` to a strong password before startup. The legacy value `primeagent` is not allowed.

To override these values, edit `docker/dev.docker-compose.yml` directly.

`docker/dev.docker-compose.yml` uses literal values in its `environment:` block, such as `- PRIMEAGENT_SUPERUSER=primeagent`. Docker Compose v2 gives `environment:` block literal values higher precedence than shell-exported variables and `env_file:`, so neither `export PRIMEAGENT_SUPERUSER=myadmin` or a `.env` file will override them. Edit the file directly instead.

## Upgrade the Primeagent Docker image {#upgrade-the-primeagent-docker-image}

:::warning Check where your container stores data
Unless you set `PRIMEAGENT_DATABASE_URL` or `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true`, Primeagent stores its SQLite database inside the container, not on a mounted volume.
Unless you set `PRIMEAGENT_CONFIG_DIR` to the mounted path, Primeagent also stores its secret key and uploaded files inside the container.
Removing or recreating that container deletes this data, even if a volume is mounted.

If your current container was started without these settings, [move its data to a volume](#move-data-to-a-volume) before you upgrade.
:::

To upgrade a Primeagent Docker deployment without losing your database or flows, do the following:

1. Keep data on persistent volumes, so when you upgrade Primeagent, you will replace only the container image.
Mount a Docker volume or bind mount at the path in `PRIMEAGENT_CONFIG_DIR`, and keep the database outside of the container.
To use PostgreSQL, set `PRIMEAGENT_DATABASE_URL`. To keep SQLite, set `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true`, which stores the database in the config directory.
For example, this Docker Compose file uses a bind mount for Primeagent data (`./primeagent-data` on the host) and a named volume for the PostgreSQL database (`primeagent-postgres`):

    ```yaml
    services:
      primeagent:
        image: khulnasoft/primeagent:1.11.0
        ports:
          - "7860:7860"
        depends_on:
          - postgres
        environment:
          - PRIMEAGENT_DATABASE_URL=postgresql://primeagent:primeagent@postgres:5432/primeagent
          - PRIMEAGENT_CONFIG_DIR=/app/primeagent
          - PRIMEAGENT_SUPERUSER_PASSWORD=${PRIMEAGENT_SUPERUSER_PASSWORD}
        volumes:
          - ./primeagent-data:/app/primeagent
      postgres:
        # Pinned to a specific Debian base (trixie) so the postgres:16 tag does
        # not silently roll its OS, which triggers a glibc collation mismatch
        # warning on existing volumes. See https://github.com/khulnasoft-bot/primeagent/issues/9608
        image: postgres:16-trixie
        environment:
          POSTGRES_USER: primeagent
          POSTGRES_PASSWORD: primeagent
          POSTGRES_DB: primeagent
        volumes:
          - primeagent-postgres:/var/lib/postgresql/data

    volumes:
      primeagent-postgres:
    ```

    On Linux, if `./primeagent-data` doesn't exist, Docker creates it owned by `root`, and Primeagent fails to start with a `PermissionError`.
    Before you start Primeagent, create the directory next to the Compose file, and make the Primeagent user (UID `1000`) its owner:

    ```bash
    mkdir -p primeagent-data
    sudo chown -R 1000:0 primeagent-data
    ```

   For additional examples, see the [Docker Compose configuration](#docker-compose) and the [docker_example compose file](https://github.com/khulnasoft-bot/primeagent/blob/main/docker_example/docker-compose.yml).

2. Pull the new image and update the image tag in your `docker-compose.yml` or `docker run` command.

    With Docker Compose, set the image in your compose file, such as `image: khulnasoft/primeagent:1.11.0`, and then pull:

    ```bash
    docker compose pull
    ```

    With `docker run`, pull the image:

    ```bash
    docker pull khulnasoft/primeagent:1.11.0
    ```

3. Restart the container. The same volumes will be reattached, so your database and flows are preserved.

    With Docker Compose:

    ```bash
    docker compose up -d
    ```

    With `docker run`, stop and remove the old container, and then start a new container with the same volume mount and the new image tag:

    ```bash
    docker run -p 7860:7860 \
      -v primeagent-data:/app/primeagent \
      -e PRIMEAGENT_CONFIG_DIR=/app/primeagent \
      -e PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true \
      -e PRIMEAGENT_SUPERUSER_PASSWORD=SUPERUSER_PASSWORD \
      khulnasoft/primeagent:1.11.0
    ```

    Replace `SUPERUSER_PASSWORD` with a strong password for the Primeagent superuser.
    This command stores the SQLite database, secret key, and uploaded files in the `primeagent-data` volume.
    To use PostgreSQL instead, replace `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true` with `PRIMEAGENT_DATABASE_URL`.

This approach keeps the persistent volumes separate from the Primeagent container, so you can upgrade the Primeagent application without losing data.

### Move data from a container to a volume {#move-data-to-a-volume}

If your current container was started without `PRIMEAGENT_DATABASE_URL` or `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true`, its SQLite database is inside the container.
If it was also started without `PRIMEAGENT_CONFIG_DIR`, its secret key and uploaded files are inside the container too.
Without the original secret key, Primeagent can't decrypt saved credentials, such as **Credential** global variables.

To keep this data, copy it to a volume before you remove the container:

1. While the container is running, list the data files that are stored inside it:

    ```bash
    docker exec OLD_CONTAINER sh -c 'find / -xdev \( -name "primeagent*.db" -o -name secret_key \) 2>/dev/null'
    ```

    Replace `OLD_CONTAINER` with the name or ID of the container. To find it, run `docker ps`.
    The output lists the paths to copy. The paths depend on the image version. For example:

    ```text
    /app/data/.cache/primeagent/secret_key
    /app/.venv/lib/python3.14/site-packages/primeagent/primeagent.db
    ```

    If the output is empty, the container already stores its data on a volume or in an external database.

2. Stop the container, so SQLite writes all pending changes to the database file:

    ```bash
    docker stop -t 60 OLD_CONTAINER
    ```

    The `-t 60` option gives Primeagent up to 60 seconds to shut down before Docker kills it.

3. Copy the config directory, which is the directory that contains `secret_key`, and the database file to a backup directory on the host.
Use the paths from step 1:

    ```bash
    mkdir primeagent-backup
    docker cp OLD_CONTAINER:/app/data/.cache/primeagent/. primeagent-backup/
    docker cp OLD_CONTAINER:/app/.venv/lib/python3.14/site-packages/primeagent/primeagent.db primeagent-backup/
    ```

    If step 1 listed only the database file, skip the first `docker cp` command.
    The backup contains your secret key, so keep it private.

    Then copy the `primeagent.db-wal` and `primeagent.db-shm` files from the same directory as the database file.
    These files exist only if Primeagent didn't shut down cleanly, and they can hold changes that aren't in `primeagent.db` yet:

    ```bash
    docker cp OLD_CONTAINER:/app/.venv/lib/python3.14/site-packages/primeagent/primeagent.db-wal primeagent-backup/
    docker cp OLD_CONTAINER:/app/.venv/lib/python3.14/site-packages/primeagent/primeagent.db-shm primeagent-backup/
    ```

    If Docker reports `Could not find the file`, the database file already holds all changes.

4. Copy the backup into the volume, and make the Primeagent user (UID `1000`) the owner of the files:

    ```bash
    docker run --rm --user root \
      -v primeagent-data:/app/primeagent \
      -v "$PWD/primeagent-backup:/backup:ro" \
      khulnasoft/primeagent:1.11.0 \
      sh -c 'cp -R /backup/. /app/primeagent/ && chown -R 1000:0 /app/primeagent'
    ```

    Replace `primeagent-data` with your volume name, or with the host path of your bind mount, such as `"$PWD/primeagent-data"`.
    Docker Compose adds the project name to volume names. To find the name, run `docker volume ls`.
    With Docker Desktop, create the backup directory in a location that Docker can share, such as your home directory.

5. Start the new container with `PRIMEAGENT_CONFIG_DIR=/app/primeagent` and `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true`, as shown in the `docker run` command in the [upgrade steps](#upgrade-the-primeagent-docker-image).
With Docker Compose, add `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true` to the `environment` list.
Don't point `PRIMEAGENT_DATABASE_URL` at a new PostgreSQL database for this data. That database starts empty, because Primeagent doesn't copy SQLite data into it.

6. Sign in, and confirm that your flows, API keys, and files are present. Then remove the old container:

    ```bash
    docker rm OLD_CONTAINER
    ```

If you need to upgrade to a custom image based on a Primeagent release, such as to add `uv` in `1.8.0`, first build a derived image from the official image, and then follow the same steps above.
Set the custom image in your compose file or `docker run`, and then pull and restart.

For a minimal Dockerfile that adds `uv` to the 1.8.0 image, see the [release notes](/release-notes) ("Docker image no longer includes uv or uvx").

## Docker image defaults {#docker-image-security-defaults}

As of Primeagent 1.11.x, official Primeagent Docker images set `PRIMEAGENT_AUTO_LOGIN=false` at image build time.
The Primeagent application default for non-Docker installs remains `true`.

Because auto-login is disabled, you must set `PRIMEAGENT_SUPERUSER_PASSWORD` (and optionally `PRIMEAGENT_SUPERUSER`) unless you explicitly set `PRIMEAGENT_AUTO_LOGIN=true`.

```bash
docker run -p 7860:7860 \
  -e PRIMEAGENT_AUTO_LOGIN=true \
  -e PRIMEAGENT_SUPERUSER_PASSWORD=SUPERUSER_PASSWORD \
  khulnasoft/primeagent:latest
```

For more information, see [Component hardening for untrusted users](/api-keys-and-authentication#multi-tenant-component-hardening) and [Block custom components](/deployment-block-custom-components).
