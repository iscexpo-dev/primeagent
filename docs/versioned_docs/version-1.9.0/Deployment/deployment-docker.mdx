Running applications in Docker containers ensures consistent behavior across different systems and eliminates dependency conflicts.

You can use the Primeagent Docker image to start a Primeagent container.

This guide demonstrates several ways to deploy Primeagent with [Docker](https://docs.docker.com/) and [Docker Compose](https://docs.docker.com/compose/):

* [Quickstart](#quickstart): Start a Primeagent container with default values.
* [Use Docker Compose](#clone): Clone the Primeagent repo, and then use Docker Compose to build the Primeagent Docker container.
This option provides more control over the configuration, including a persistent PostgreSQL database service, while still using the base Primeagent Docker image.
* [Create a custom flow image](#package-your-flow-as-a-docker-image): Use a Dockerfile to package a flow as a Docker image.
* [Create a custom Primeagent image](#customize-the-primeagent-docker-image): Use a Dockerfile to package a custom Primeagent Docker image that includes your own code, custom dependencies, or other modifications.
* [Upgrade the Primeagent Docker image](#upgrade-the-primeagent-docker-image): Upgrade to a newer image without losing your database or flows by using persistent volumes and replacing only the container.

## Quickstart: Start a Primeagent container with default values {#quickstart}

With Docker installed and running on your system, run the following command:

```shell
docker run -p 7860:7860 khulnasoft/primeagent:latest
```

Then, access Primeagent at `http://localhost:7860/`.

This container runs a pre-built Docker image with default settings.
For more control over the configuration, see [Clone the repo and run the Primeagent Docker container](#clone).

## Clone the repo and run the Primeagent Docker container {#clone}

Cloning the Primeagent repository and using Docker Compose gives you more control over your configuration, allowing you to customize environment variables, use a persistent PostgreSQL database service (instead of the default SQLite database), and include custom dependencies.

The default deployment with Docker Compose includes the following:

- **Primeagent service**: Runs the latest Primeagent image with PostgreSQL as the database.
- **PostgreSQL service**: Provides persistent data storage for flows, users, and settings.
- **Persistent volumes**: Ensures your data survives container restarts.

The complete Docker Compose configuration is available in `docker_example/docker-compose.yml`.

1. Clone the Primeagent repository:

   ```shell
   git clone https://github.com/khulnasoft-bot/primeagent.git
   ```

2. Navigate to the `docker_example` directory:

   ```shell
   cd primeagent/docker_example
   ```

3. Run the Docker Compose file:

   ```shell
   docker compose up
   ```

4. Access Primeagent at `http://localhost:7860/`.

### Customize your deployment

You can customize the Docker Compose configuration to fit your specific deployment.

For example, to configure the container's database credentials using a `.env` file, do the following:

1. Create a `.env` file with your database credentials in the same directory as `docker-compose.yml`:

    ```text
    # Database credentials
    POSTGRES_USER=myuser
    POSTGRES_PASSWORD=mypassword
    POSTGRES_DB=primeagent

    # Primeagent configuration
    PRIMEAGENT_DATABASE_URL=postgresql://myuser:mypassword@postgres:5432/primeagent
    PRIMEAGENT_CONFIG_DIR=/app/primeagent
    ```

2. Modify the `docker-compose.yml` file to reference the `.env` file for both the `primeagent` and `postgres` services:

    ```yaml
    services:
      primeagent:
        environment:
          - PRIMEAGENT_DATABASE_URL=${PRIMEAGENT_DATABASE_URL}
          - PRIMEAGENT_CONFIG_DIR=${PRIMEAGENT_CONFIG_DIR}
      postgres:
        environment:
          - POSTGRES_USER=${POSTGRES_USER}
          - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
          - POSTGRES_DB=${POSTGRES_DB}
    ```

For a complete list of available environment variables, see [Primeagent environment variables](/environment-variables).

For more customization options, see [Customize the Primeagent Docker image with your own code](#customize-the-primeagent-docker-image).

## Package your flow as a Docker image {#package-your-flow-as-a-docker-image}

This section shows you how to create a Dockerfile that builds a Docker image containing your Primeagent flow. This approach is useful when you want to distribute a specific flow as a standalone container or deploy it to environments like Kubernetes.

Unlike the previous sections that use pre-built images, this method builds a custom image with your flow embedded inside it.

1. Create a project directory, and change directory into it.

    ```bash
    mkdir primeagent-custom && cd primeagent-custom
    ```

2. Add your flow's JSON file to the directory. You can download an example, or use your own:

    ```bash
    # Download an example flow
    wget https://raw.githubusercontent.com/khulnasoft-bot/primeagent-helm-charts/refs/heads/main/examples/flows/basic-prompting-hello-world.json

    # Or copy your own flow file
    cp /path/to/your/flow.json .
    ```

3. Create a Dockerfile to build your custom image:

    ```dockerfile
    FROM khulnasoft/primeagent:latest
    RUN mkdir /app/flows
    COPY ./*.json /app/flows/
    ENV PRIMEAGENT_LOAD_FLOWS_PATH=/app/flows
    ```

This Dockerfile uses the official Primeagent image as the base, creates a directory for your flows, copies your JSON flow files into the directory, and sets the environment variable to tell Primeagent where to find the flows.

4. Build and test your custom image:

    ```bash
    docker build -t myuser/primeagent-custom:1.0.0 .
    docker run -p 7860:7860 myuser/primeagent-custom:1.0.0
    ```

5. Push your image to Docker Hub (optional):

    ```bash
    docker push myuser/primeagent-custom:1.0.0
    ```

Your custom image now contains your flow and can be deployed anywhere Docker runs. For Kubernetes deployment, see [Deploy the Primeagent production environment on Kubernetes](/deployment-kubernetes-prod).

## Customize the Primeagent Docker image with your own code {#customize-the-primeagent-docker-image}

While the previous section showed how to package a flow with a Docker image, this section shows how to customize the Primeagent application itself. This is useful when you need to add custom Python packages or dependencies, modify Primeagent's configuration or settings, include custom components or tools, or add your own code to extend Primeagent's functionality.

This example demonstrates how to customize the **Message History** component, but the same approach can be used for any code modifications.

```dockerfile
FROM khulnasoft/primeagent:latest

# Set working directory
WORKDIR /app

# Copy your modified memory component
COPY src/wfx/src/wfx/components/helpers/memory.py /tmp/memory.py

# Find the site-packages directory where primeagent is installed
RUN python -c "import site; print(site.getsitepackages()[0])" > /tmp/site_packages.txt

# Replace the file in the site-packages location
RUN SITE_PACKAGES=$(cat /tmp/site_packages.txt) && \
    echo "Site packages at: $SITE_PACKAGES" && \
    mkdir -p "$SITE_PACKAGES/primeagent/components/helpers" && \
    cp /tmp/memory.py "$SITE_PACKAGES/primeagent/components/helpers/"

# Clear Python cache in the site-packages directory only
RUN SITE_PACKAGES=$(cat /tmp/site_packages.txt) && \
    find "$SITE_PACKAGES" -name "*.pyc" -delete && \
    find "$SITE_PACKAGES" -name "__pycache__" -type d -exec rm -rf {} +

# Expose the default Primeagent port
EXPOSE 7860

# Command to run Primeagent
CMD ["python", "-m", "primeagent", "run", "--host", "0.0.0.0", "--port", "7860"]
```

To use this custom Dockerfile, do the following:

1. Create a directory for your custom Primeagent setup:

    ```bash
    mkdir primeagent-custom && cd primeagent-custom
    ```

2. Create the necessary directory structure for your custom code.
In this example, Primeagent expects `memory.py` to exist in the `/helpers` directory, so you create a directory in that location.

    ```bash
    mkdir -p src/wfx/src/wfx/components/helpers
    ```

3. Place your modified `memory.py` file in the `/helpers` directory.

4. Create a new file named `Dockerfile` in your `primeagent-custom` directory, and then copy the Dockerfile contents shown above into it.

5. Build and run the image:

    ```bash
    docker build -t myuser/primeagent-custom:1.0.0 .
    docker run -p 7860:7860 myuser/primeagent-custom:1.0.0
    ```

This approach can be adapted for any other components or custom code you want to add to Primeagent by modifying the file paths and component names.

## Upgrade the Primeagent Docker image {#upgrade-the-primeagent-docker-image}

:::warning Check where your container stores data
Unless you set `PRIMEAGENT_DATABASE_URL` or `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true`, Primeagent stores its SQLite database inside the container, not on a mounted volume.
Unless you set `PRIMEAGENT_CONFIG_DIR` to the mounted path, Primeagent also stores its secret key and uploaded files inside the container.
Removing or recreating that container deletes this data, even if a volume is mounted.

If your current container was started without these settings, [move its data to a volume](#move-data-to-a-volume) before you upgrade.
:::

To upgrade a Primeagent Docker deployment without losing your database or flows, do the following:

1. Keep data on persistent volumes, so when you upgrade Primeagent, you will replace only the container image.
Mount a Docker volume or bind mount at the path in `PRIMEAGENT_CONFIG_DIR`, and keep the database outside of the container.
To use PostgreSQL, set `PRIMEAGENT_DATABASE_URL`. To keep SQLite, set `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true`, which stores the database in the config directory.
For example, this Docker Compose file uses a bind mount for Primeagent data (`./primeagent-data` on the host) and a named volume for the PostgreSQL database (`primeagent-postgres`):

    ```yaml
    services:
      primeagent:
        image: khulnasoft/primeagent:1.8.0
        ports:
          - "7860:7860"
        depends_on:
          - postgres
        environment:
          - PRIMEAGENT_DATABASE_URL=postgresql://primeagent:primeagent@postgres:5432/primeagent
          - PRIMEAGENT_CONFIG_DIR=/app/primeagent
        volumes:
          - ./primeagent-data:/app/primeagent
      postgres:
        image: postgres:16
        environment:
          POSTGRES_USER: primeagent
          POSTGRES_PASSWORD: primeagent
          POSTGRES_DB: primeagent
        volumes:
          - primeagent-postgres:/var/lib/postgresql/data

    volumes:
      primeagent-postgres:
    ```

    On Linux, if `./primeagent-data` doesn't exist, Docker creates it owned by `root`, and Primeagent fails to start with a `PermissionError`.
    Before you start Primeagent, create the directory next to the Compose file, and make the Primeagent user (UID `1000`) its owner:

    ```bash
    mkdir -p primeagent-data
    sudo chown -R 1000:0 primeagent-data
    ```

   For additional examples, see the [Docker Compose configuration](#clone) and the [docker_example compose file](https://github.com/khulnasoft-bot/primeagent/blob/main/docker_example/docker-compose.yml).

2. Pull the new image and update the image tag in your `docker-compose.yml` or `docker run` command.

    With Docker Compose, set the image in your compose file, such as `image: khulnasoft/primeagent:1.8.0`, and then pull:

    ```bash
    docker compose pull
    ```

    With `docker run`, pull the image:

    ```bash
    docker pull khulnasoft/primeagent:1.8.0
    ```

3. Restart the container. The same volumes will be reattached, so your database and flows are preserved.

    With Docker Compose:

    ```bash
    docker compose up -d
    ```

    With `docker run`, stop and remove the old container, and then start a new container with the same volume mount and the new image tag:

    ```bash
    docker run -p 7860:7860 \
      -v primeagent-data:/app/primeagent \
      -e PRIMEAGENT_CONFIG_DIR=/app/primeagent \
      -e PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true \
      khulnasoft/primeagent:1.8.0
    ```

    This command stores the SQLite database, secret key, and uploaded files in the `primeagent-data` volume.
    To use PostgreSQL instead, replace `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true` with `PRIMEAGENT_DATABASE_URL`.

    Images `1.8.0` through `1.9.3` don't include the `/app/primeagent` directory.
    When Docker mounts a new named volume there, `root` owns the volume, and Primeagent fails to start with a `PermissionError`.
    Before you start one of these images, make the Primeagent user (UID `1000`) the owner of the volume:

    ```bash
    docker run --rm --user root \
      -v primeagent-data:/app/primeagent \
      khulnasoft/primeagent:1.8.0 \
      chown -R 1000:0 /app/primeagent
    ```

    The steps to [move data from a container to a volume](#move-data-to-a-volume) include this change of owner.

This approach keeps the persistent volumes separate from the Primeagent container, so you can upgrade the Primeagent application without losing data.

### Move data from a container to a volume {#move-data-to-a-volume}

If your current container was started without `PRIMEAGENT_DATABASE_URL` or `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true`, its SQLite database is inside the container.
If it was also started without `PRIMEAGENT_CONFIG_DIR`, its secret key and uploaded files are inside the container too.
Without the original secret key, Primeagent can't decrypt saved credentials, such as **Credential** global variables.

To keep this data, copy it to a volume before you remove the container:

1. While the container is running, list the data files that are stored inside it:

    ```bash
    docker exec OLD_CONTAINER sh -c 'find / -xdev \( -name "primeagent*.db" -o -name secret_key \) 2>/dev/null'
    ```

    Replace `OLD_CONTAINER` with the name or ID of the container. To find it, run `docker ps`.
    The output lists the paths to copy. The paths depend on the image version. For example:

    ```text
    /app/data/.cache/primeagent/secret_key
    /app/.venv/lib/python3.12/site-packages/primeagent/primeagent.db
    ```

    If the output is empty, the container already stores its data on a volume or in an external database.

2. Stop the container, so SQLite writes all pending changes to the database file:

    ```bash
    docker stop -t 60 OLD_CONTAINER
    ```

    The `-t 60` option gives Primeagent up to 60 seconds to shut down before Docker kills it.

3. Copy the config directory, which is the directory that contains `secret_key`, and the database file to a backup directory on the host.
Use the paths from step 1:

    ```bash
    mkdir primeagent-backup
    docker cp OLD_CONTAINER:/app/data/.cache/primeagent/. primeagent-backup/
    docker cp OLD_CONTAINER:/app/.venv/lib/python3.12/site-packages/primeagent/primeagent.db primeagent-backup/
    ```

    If step 1 listed only the database file, skip the first `docker cp` command.
    The backup contains your secret key, so keep it private.

    Then copy the `primeagent.db-wal` and `primeagent.db-shm` files from the same directory as the database file.
    These files exist only if Primeagent didn't shut down cleanly, and they can hold changes that aren't in `primeagent.db` yet:

    ```bash
    docker cp OLD_CONTAINER:/app/.venv/lib/python3.12/site-packages/primeagent/primeagent.db-wal primeagent-backup/
    docker cp OLD_CONTAINER:/app/.venv/lib/python3.12/site-packages/primeagent/primeagent.db-shm primeagent-backup/
    ```

    If Docker reports `Could not find the file`, the database file already holds all changes.

4. Copy the backup into the volume, and make the Primeagent user (UID `1000`) the owner of the files:

    ```bash
    docker run --rm --user root \
      -v primeagent-data:/app/primeagent \
      -v "$PWD/primeagent-backup:/backup:ro" \
      khulnasoft/primeagent:1.8.0 \
      sh -c 'cp -R /backup/. /app/primeagent/ && chown -R 1000:0 /app/primeagent'
    ```

    Replace `primeagent-data` with your volume name, or with the host path of your bind mount, such as `"$PWD/primeagent-data"`.
    Docker Compose adds the project name to volume names. To find the name, run `docker volume ls`.
    With Docker Desktop, create the backup directory in a location that Docker can share, such as your home directory.

5. Start the new container with `PRIMEAGENT_CONFIG_DIR=/app/primeagent` and `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true`, as shown in the `docker run` command in the [upgrade steps](#upgrade-the-primeagent-docker-image).
With Docker Compose, add `PRIMEAGENT_SAVE_DB_IN_CONFIG_DIR=true` to the `environment` list.
Don't point `PRIMEAGENT_DATABASE_URL` at a new PostgreSQL database for this data. That database starts empty, because Primeagent doesn't copy SQLite data into it.

6. Open Primeagent, sign in if Primeagent asks you to, and confirm that your flows, API keys, and files are present. Then remove the old container:

    ```bash
    docker rm OLD_CONTAINER
    ```

If you need to upgrade to a custom image based on a Primeagent release, such as to add `uv` in `1.8.0`, first build a derived image from the official image, and then follow the same steps above.
Set the custom image in your compose file or `docker run`, and then pull and restart.

For a minimal Dockerfile that adds `uv` to the 1.8.0 image, see the [release notes](/release-notes) (“Docker image no longer includes uv or uvx”).
